# Inburgering project

Work locally unless the user explicitly asks to publish. Keep credentials in `.env`, private official reference material in `reference-private/` and report databases in `var/`; all three are ignored by Git.

For exercise authoring, evidence changes and review, follow [content/blueprint.md](content/blueprint.md) (what each exercise must look like per exam part, tags, audio, images, topics to avoid, the sub-agent workflow), [docs/research/content-workflow.md](docs/research/content-workflow.md) and [content/reviews/rubric.md](content/reviews/rubric.md). Scope is A2, KNM and B1; B2 is out of scope. Use a separate author and reviewer when producing a batch. The reviewer must read the full final source and verify current official sources for KNM. Integrate only passing hash-verified batches through `npm run content:integrate`. Do not describe AI editorial review as validated CEFR difficulty or exam equivalence.

The runtime is React Router framework mode, TypeScript and Vite. Use route loaders/actions for backend work. Do not restore a Python backend or the legacy esbuild entry. Run `npm run dev` for hot reload. SQLite in `var/reports.sqlite3` stores reports, published exercises, drafts, history and aggregate service usage. Admin edits are drafts until independently reviewed; archive instead of destroying exercises. See docs/research/infrastructure.md for APIs, backup and local admin access. Use `npm run check` and `npm run test:browser` for validation. `npm run check` enforces Prettier formatting (run `npm run format` before finishing) and a 1200-line limit per source file; split a file rather than grow it. Browser tests own an isolated server, database and Firefox profile; they use synthetic provider credentials.

For interface work, preserve the accepted layout and the single editable speaking transcript. Use plain CSS, unstyled Base UI controls and the local Public Sans font. Keep filters stable when labels become bold. Read DESIGN.md before changing layout or colours. Verify affected journeys in Firefox with an isolated profile, including a narrow viewport and failure recovery. Never clear the user's own browser data for testing.

Use the existing cheap feedback model unless a bounded synthetic evaluation supports changing it. See docs/research/feedback-latency.md. Never print API keys or embed them in browser assets.

Listening audio uses voice roles from `config/voices.json` (native Netherlands Dutch voices only, two roles per conversation) and `scripts/audio.ts`, which generates from reviewed scripts, checks every clip with a transcription round trip and records a manifest. Generate audio only after a batch has passed review.
