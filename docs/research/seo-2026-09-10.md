# Search and shareable URLs

Updated 10 September 2026. Changes run locally. This server has no public domain and cannot be indexed by Google.

## Implemented

Language-skill catalogues now use `/a2/reading`, `/b1/listening`, `/b2/writing` and the corresponding paths for the other skills. Practice-test setup and local progress also carry the level. A shared explicit URL takes priority over cookies and browser storage, including on first server render and browser Back/Forward. The level controls are real links with their existing appearance and indicator animation; opening another level in a new tab works normally.

KNM keeps `/knm` because it is independent of language proficiency. Exercises retain their stable `/exercise/<encoded-id>` paths, whose existing language-exercise IDs already identify their level. Sets retain addresses such as `/sets/a2-listening-01`. Those routes resolve their level from the published content, preserving existing shared links and local records. A future readable exercise slug should be stored as a permanent alias, with redirects when needed; do not derive it afresh from an editable title.

Unqualified legacy catalogue links redirect with HTTP 307 to the saved level, or A2 without a preference cookie. Uppercase level prefixes and trailing slashes redirect permanently with HTTP 308 to the canonical spelling. Unsupported levels and invalid route combinations return 404. Bare `/a2`, `/b1` and `/b2` lead to that level's reading page. Normal internal links point directly to canonical paths.

The server renders the actual task HTML. Each skill/level has its own title, description and canonical link; individual exercises and sets have task-specific metadata. Open Graph and Twitter summary metadata supply a title and description for sharing. We have not invented a preview image or production-domain URL.

Each page also has an address per interface language. The plain path is Dutch, the default; `/en` precedes the rest of the English address (`/en`, `/en/a2/reading`, `/en/sets/a2-listening-01`, `/en/exercise/…`), and the address decides the language on the server and in the browser. A browser whose preference cookie says English is sent from a plain path to its `/en` twin with HTTP 307 (never cached), a crawler or first visit finds Dutch there, and `/en` is English whatever the cookie says; nothing redirects on Accept-Language or location, which Google warns hides versions from crawlers. Titles and descriptions exist in both languages, every page names both versions in `hreflang` links with Dutch as `x-default`, the canonical is per language, and the language choice is a pair of real links so the versions reach each other. Only the interface is translated — the study material is Dutch in both — so the English pages that can rank for English queries are the landing pages (start, subjects, level check, About); exercise pages read as Dutch either way.

The sitemap includes populated skill/level pages, KNM, About, published exercises and available sets, each in both languages with `xhtml:link` alternates. It excludes empty B2 pages, private progress and practice-test session pages. Empty catalogues and private views send a `noindex, follow` meta tag. These views remain crawlable so a crawler can read that directive. robots.txt excludes the local admin/API paths. Private data still needs access controls when the service becomes public; robots.txt is not access control.

## Work to do next

| --- | --- |
| Review the teaching content | Have an NT2 teacher review difficulty and answer explanations. Publish an accurate account of authorship and review on About. AI editorial approval alone cannot establish exam equivalence. |
| Create useful subject introductions | Add a concise explanation of what each skill practises, with links to relevant official information. Avoid repeating generic SEO paragraphs across every level. Draft and review this as educational content before adding it to the interface. |
| Improve discovery within a set | Add a compact, visible list of its exercise titles when that fits the practice flow. The sitemap lists individual exercises today, but a crawlable table of contents would help visitors discover and share them. |
| Add structured data for visible content | BreadcrumbList can describe a visible level/subject/exercise hierarchy. Do this alongside actual breadcrumbs; avoid fictitious course credentials, reviews, exam results or claims of guaranteed rich results. |
| Measure page performance | Check Core Web Vitals under mobile throttling and field traffic after launch. Current tests verify first-response task HTML and hydration stability; they do not measure real-user LCP, INP or CLS. Review route payload size, fonts and player decoding with measurements before optimizing. |
| Prepare public hosting | Choose the HTTPS domain, configure the canonical origin and redirects, implement public admin authentication, and revisit the current loopback/cross-site restrictions. Add a favicon and a deliberate preview image when the identity is settled. |
| Verify the launched site | Register the domain in Search Console, submit the sitemap, inspect representative A2/B1/task URLs, and check indexing, crawl errors and real-user performance. Indexing remains Google's decision. |

Do not generate hundreds of near-duplicate landing pages just to target keyword variations. New pages should answer a learner's question or provide a distinct exercise.

## Sources consulted

- [Google: URL structure](https://developers.google.com/search/docs/crawling-indexing/url-structure), readable paths, ordinary URLs rather than content-changing fragments, and avoiding excessive parameter combinations.
- [Google: canonical URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), consistent canonical links, redirects and sitemap entries.
- [Google: robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro), the difference between preventing crawling and preventing indexing.
- [Google: multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites), distinct URLs for language versions and discoverable alternatives.
- [Google: structured data](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data), describing the page's content and eligibility without a promise of search enhancements.

## Validation

Route and SEO tests cover level and language round trips, invalid prefixes, distinct metadata per level and language, alternates and sitemap exclusion of empty pages. Firefox checks cover cookie conflicts, copied paths, level navigation and history. Production checks inspect the server HTML, redirects, noindex and sharing metadata. All tests use isolated browser profiles and databases.
