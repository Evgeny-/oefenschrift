# Inburgering design

Use `design-with-restraint`. The user accepted the subject navigation and exercise workspace. Keep neutral surfaces, custom colour tokens and locally hosted Public Sans. Use plain CSS without Tailwind or a component theme.

“Inburgering” is the user-approved working name. The app was rebuilt in React from the accepted layout. Each level is a single-click navigation link, with its own URL. Language, theme and playback speed use unstyled Base UI radio groups. All retain the compact segmented appearance. Keyboard focus remains visible; radio groups support arrow navigation and level links support ordinary browser link gestures.

The play button uses a centered SVG and a 44px circular target. Waveforms derive from the real recording; changing speed or interface language preserves playback. The workspace uses a flex column so its footer reaches the viewport bottom on short pages and follows content on longer pages.

The root follows the browser default (100%). Interface sizes were tuned so the layout keeps its previous feel rather than growing 10%: .8125rem for labels and supporting text, .9375rem for navigation and interface text, 1.125rem for section headings and 1.875rem for page headings and the result total. Dutch study material (passages, prompts, answer options, explanations, the answer field) uses a separate 1.0625rem reading size with a 1.75 line height, so the material is larger than the interface around it. Sidebar captions and sheet labels use a .6875rem uppercase micro label with .09em tracking. Keep comfortable touch targets through the coarse-pointer rules. Use only the supplied 400 and 600 font weights; the user rejected a serif for the material as too eye-catching. Group labels close to controls, with larger separation between tasks. Place the Inburgering wordmark at the top of the sidebar with a marker highlight behind its lower half (the evidence marker is the identity), with level choices beneath it. Levels without reviewed material stay visible as a muted placeholder titled Binnenkort. Subject and utility links carry a 16px single-weight stroke icon that inherits the label colour at 70% opacity; the icons are hidden on phones. Each icon has one small motion that plays once when the learner navigates to its section (a real section change after load — sidebar click or a back link), never on page load and never on hover: the book opens, the headphones nod, the pen tilts and writes a line, the microphone sends out two waves, the windmill's sails turn a quarter, the stopwatch hand sweeps, the bars grow. The motion is CSS only (transform-box: view-box), lasts under a second and is disabled under reduced motion. Language and theme controls in the sidebar are compact (1.75rem choices, 18px flags, 14px icons) so they stay subordinate to navigation; the phone popover keeps the larger touch size. Language uses circular Dutch and British flag choices with accessible language names; theme uses named sun, moon and monitor icons. Both groups put their label above the control, aligned at the left. Their widths follow the number of choices. On mobile the wordmark and level share a row. All five subject links stay visible underneath, followed by Practice test and Progress. Language and theme move together into a small preferences popover; levels and subjects stay outside it. Keep side padding at 320px and 390px.

All subjects open a catalogue of short practice sets, each containing three to five exercises from the same subject and level. Continue through a set before showing its result. Offer the next set at completion, and preserve a separate unfinished session for each set when navigating away. English changes interface and feedback copy; Dutch exercise content stays Dutch. Progress, drafts and the current test survive reload and migrate from the previous prototype’s local storage. AI feedback and self-review remain distinct from quiz accuracy. Avoid official pass predictions.

The user authorized local API use. Feedback uses a server-side OpenAI key, and generated audio reuses the Dutch project’s ElevenLabs voice settings. Explain sending an answer at the feedback action. This authorization does not change the earlier cancellation of publication.

Controls keep the same text weight in every state. Level and language choices have fixed widths; speed choices reserve room for their longest label. A borderless rounded indicator animates to the selected choice without moving the labels. Settings have no outer border either. Center each flag inside its choice. Measure indicator positions with fractional bounding rectangles; rounded offset measurements can leave the active circle visibly off center. On initial paint, place the indicator at the persisted value without animation; only subsequent changes animate, after fonts and initial measurements settle. Filter labels may become bold, with their bold width reserved in advance. The timer reserves a fixed area even when its elapsed readout is hidden. Coarse-pointer targets grow without widening the desktop toolbar.

Use saturated golden yellow for primary actions: `#efbf24` in light mode and `#edc343` in dark mode, both with dark text. The light ground is a deeper warm paper (`#f3efe6`) so that study material can sit on a lifted sheet (`#fffdf9`, hairline `#e4ded0`, a 1px bottom rule instead of a shadow); dark surfaces use neutral charcoal (`#242424`) with a slightly lighter sheet (`#2c2c2a`). The sheet carries reading passages, listening players, writing and speaking briefs and the example answer, each with an uppercase label naming the text type (bericht, mededeling, e-mail, advertentie, informatie) or the task. Navigation uses neutral states; selected settings use softer yellow (#f3dfa0 with #423818 text in light mode, #726132 with #fff0c3 text in dark mode); exercise filters use a saturated yellow underline. List rows are transparent with a restrained rounded hover surface in the sheet colour, separated by hairlines. Every surface and feedback state uses semantic CSS variables. Light, Dark and System are explicit choices. System is the default, follows OS changes and resolves before rendering; existing saved Light or Dark preferences remain intact. Avoid ornamental gradients and shadows; the phone question sheet is the one element with a soft upward shadow, because it floats over scrolling text.

Put the feedback disclosure and Privacy link in a Base UI popover, opened by a small information icon beside the feedback action only; once feedback is shown, the Next/Finish button carries no icon, because the sending it explains has already happened. Support hover, keyboard and click. Put a second information icon beside Record. Its popup explains external speech recognition after stopping, the two-minute / 6 MB recording limits, transcript editing and Privacy. Provider names and retention details belong in the privacy document. Every exercise type uses the same title, subtitle and control group with elapsed time and Report a problem. Base UI handles the report dialog, focus trap, Escape and focus return. Practice-test setup uses Base UI Switch for elapsed time, retaining its native hidden checkbox. Its 32×20px track and 14px thumb have equal 3px end gaps and 12px travel. The surrounding label retains a comfortable hit area. Animate the thumb and track colour; the label cannot be accidentally selected.

Speaking has one answer workspace. Stopping the recording transcribes it into an editable field; the transcription boundary is explained in the information popup beside Record. Remove the duplicate transcript card and secondary sample/self-review actions from the online speaking flow. Feedback occupies that same column. Missing or uncertain criteria start expanded. Language changes translate the same canonical assessment without issuing another judgment, including while a request is pending. Task summaries derive from those decisions. Show available suggested revisions immediately with the note that other wording can work and meaning should be checked. Show a suggested answer even when requirements are missing. Leave missing details as Dutch bracket placeholders for the learner to fill. If the model omits a suggestion or enough placeholders, use the submitted text plus the missing Dutch rubric labels in brackets. Do not hide an unchanged answer: explain that the wording can remain. The placeholder check does not prove factual fidelity, so retain the short meaning-check note. Edit answer restores the form. Keep the submitted answer separately so a diff always compares against the exact text assessed.

Pale yellow marks text selection, correct-answer evidence and proposed insertions. The stronger yellow belongs to primary actions and the exercise-filter underline; selected settings use the softer tab tokens while navigation remains neutral. Wrong selected options use a strike-through, and removed words remain readable. Use exact reviewed source quotes; never guess an evidence highlight from keyword similarity. Additions in AI rewrites are suggestions and must be checked for factual accuracy.

Preserve the contained sidebar-and-content layout, centered with a maximum width of 72rem and a 12rem sidebar (80rem read as too wide once the root moved to 100%). The user rejected the full-width shell and separate header. Back sits within the content column and names the subject (Terug naar Lezen); the toolbar's right side names the set and the current text, clip or task (Oefenset 1 · tekst 1 van 5), while the question count and a thin ink progress bar sit above the columns. Level selection belongs in the sidebar. The sidebar shares the page background; do not give it a gray panel. Active navigation uses darker, heavier text without bars, dots or a filled block; each label reserves its bold width with a hidden zero-height copy (the same device as the exercise filters), so switching sections never shifts the neighbouring links, which mattered most in the phone row. Keep the sidebar free of slogans and duplicate progress counters. The working name appears as a quiet sidebar wordmark and in the page title. Language and theme share the same label-above-control arrangement with compact widths. Preserve single-click settings and check long Dutch labels for spacing. The footer spreads across the content column on desktop, the unofficial-practice notice at the left and the document links at the right; on phones it centres and wraps.

Keep the stylesheet organised by component and maintain one definition for each typographic role. Replace obsolete rules when revising a component; avoid adding another competing type scale at the end of the file.

One border colour serves sheets, text fields, answer choices and secondary buttons: `#ddd6c4` in light mode and `#4a4946` in dark mode (`--sheet-line` and `--control-border` share it). Two radii cover everything: `--radius-control` (.5rem) for buttons, inputs, options, keycaps and small popups, `--radius-surface` (.75rem) for sheets, the audio player, list-row hover, cards, dialogs and the phone question sheet; only pills and circles differ. Hovered choices and secondary buttons use the stronger control-hover token. Selected choices keep their filled surface and contrasting letter marker with a medium border. Preserve the distinct keyboard-focus outline. The timer switch retains its own track contrast.

Report dialogs fade and move over 180ms on entry and exit. Their height adapts over 200ms when the form becomes a compact confirmation with its receipt and a return button. Honor reduced motion. Keep unsent details after a failure or dismissal; reset a successful form after it has finished closing. Base UI retains its focus trap, Escape and focus return.

Open tasks offer optional reviewed Dutch sentence starters under the criteria. Keep them partial, in criteria order, and outside the answer field. They never overwrite a draft or supply a complete response. Omit routine “Draft saved” text while retaining actual storage failure notices and transcript-check guidance.

Speaking recordings reuse the listening playback controls. The audio player is a sheet (surface radius); under the waveform the elapsed time and a small unlabelled speed control (1.5rem pills, .75rem text, an sr-only Snelheid label) sit together at the left. Generate 64 waveform bins from the actual decoded audio locally, using RMS energy across channels and time windows. Retain a plain seek bar if decoding is unavailable. Use decoded duration when recording metadata lacks a finite duration. Omit the “Synthetic sample voice” caption from the player. The About page explains that listening clips use generated Dutch speech. Changing language or speed preserves the player; recording again pauses the previous audio and a replacement clip starts at zero.

Completed exercise rows show a small unfilled check and muted status text at the right. Drafts use the same status position. Avoid filled badges, bold completion labels and repetitive “Not started” copy. A completion check means the exercise was finished, not that every answer was correct. Keep meaningful scores in supporting text. Catalogue set rows name their texts on a second line, state the unit count, question count and text types in supporting text, and end with a 2.75rem progress ring (2.5px stroke): yellow while a set is in progress, ink once it is complete, with an answered/total label drawn as SVG text anchored on the circle centre (10px, baseline offset by half the cap height) so 10/10 sits optically centred in every browser; the arc uses butt caps so its start aligns exactly with twelve o'clock. No status words duplicate the ring: an unfinished set shows only its partial ring, a completed set a full ink ring, and only a completed closed set adds its first score (7 van 8 goed) as quiet text. The state and count are still spoken to screen readers. Individual exercises in Progress keep the quiet status and chevron.

Closed questions accept keyboard answers: 1, 2, 3 (and the option letters) select an option; Enter checks the answer or continues. Enter is ignored while a button, link or text field has focus so native activation is not doubled. On devices with a fine pointer the primary button carries a return-arrow glyph on a translucent keycap (no border); the options show no digit hints, because their A/B/C markers already double as keys and a second set of numbers read as redundant. The About page names the keys once. The question progress bar fills in action yellow at 3px so it does not disappear against the paper. It counts answered questions and advances the moment an answer is checked (on Next in a practice test), so “Vraag 5 van 8” shows four eighths on arrival and five once checked; it never reaches the end before the last answer is in. On phones the question section becomes a fixed bottom sheet over the scrolling text, with a handle button that collapses it to the prompt (Tekst tonen / Vraag tonen); the columns keep bottom padding equal to the sheet height so the last lines of the passage can scroll above it. Listening transcripts open only after an answer has been checked in practice mode and never in a practice test.

Set results use two columns from 64rem: score, per-text breakdown, actions and the folded full list at the left; the mistakes at the right. Below that width they stack in reading order (score, mistakes, actions). They show the score, a per-text breakdown for sets, and the mistakes grouped by the reviewed skill of each question (falling back to the exercise title), each with the learner's answer struck through, the correct answer, the exact evidence and the explanation. The primary action is a focused retry of only the missed questions: the session keeps the set's URL and exercise list and narrows its questions; on completion it updates only the retried responses so saved mistakes clear while the first score and date stay. Next set stays available beside it and the full list of questions folds under a disclosure.

Every exercise uses a stable `/exercise/<encoded-id>` URL, for open and closed tasks alike. Links support normal browser copy, new-tab and history behavior. Legacy hash links redirect to the corresponding path. Local progress belongs to this browser and is not encoded in the shared URL. Keep normal routes working on direct requests and reloads; missing assets must remain 404s. Version app assets on build and prevent stale shell caching without clearing the learner’s saved work.

The catalogue lists sets newest first (highest number at the top), because sets are added periodically and returning learners should see the additions without scrolling; Volgende set still moves up the numbers. Practice sets have stable `/sets/<set-id>` links alongside individual exercise URLs. Their explicit membership lives in `content/practice-sets.json`; do not repartition existing sets when adding content. The build verifies complete catalogue coverage, unique membership and matching subject/level. Set sessions save their question position, selections and checks independently. Writing and speaking advance after review, preserving each draft and completion record. These short practice sets do not establish official exam length or difficulty.

Progress offers a JSON export of records, drafts and self-review checks, and an import that validates the file through the same restore path; imported results replace local ones only when newer and imported drafts fill only empty local drafts. Progress has one list with separate Drafts, Completed and Review mistakes filters. Never append drafts beneath a different active filter. Align exercise and set titles with the page heading before hover. Give each row 1rem of horizontal padding and an equal negative margin, so the full rounded surface is clickable without shifting the text. At narrow widths use .75rem padding with a visible outer margin. Fade one pseudo-element covering the row; do not combine a background transition with an extending shadow.

Place elapsed time and Report a problem together beside the level/subject metadata, with wrapping when needed. The clock reads in minutes (< 1 min, 7 min, 1 u 05 min) so it never ticks distractingly; results show the same “Oefentijd”. It counts only active time: seconds accumulate while the exercise is on screen and the tab is visible, are folded into the session (or the exercise timer for standalone open tasks) every five seconds and when the view leaves, and never include time away, reloads or closed tabs. There are no start timestamps to reconcile; a legacy timestamp in saved data is dropped. Speaking groups Record and its information icon beside a reversible Type instead / Hide text field action. Do not push the typing action to the far edge or offer audio uploads. Hiding typed input preserves its draft. Label the hint disclosure Sentence starters / Beginzinnen, using an underlined label and a small SVG chevron on a transparent surface. Rotate the chevron on expansion. Keep focus outlines within or close to controls, with no large offset that reaches adjacent text.

Render the actual exercise and navigation on the server. Use the same initial state during hydration, with CSS selecting the mobile layout. Preferences and the current public set position are mirrored in cookies so reload starts with the appropriate view. Answers, drafts and results restore from local browser storage and remain absent from those cookies.

Level navigation uses real links such as `/a2/reading` and `/b1/listening`, retaining its existing compact appearance and animated indicator. The URL determines the selected proficiency level; browser history and copied links must preserve it. KNM has one independent route. Theme, language and speed remain radio choices.

The operations panel at `/ops` is an operator tool, so it uses a top bar instead of the learner sidebar: wordmark, an uppercase Administration tag, underline tabs (Overview, Exercises, Reports with an open count, Services) and Sign out. Everything sits on sheets: stat tiles with a micro label, a 1.75rem tabular number and one line of detail; cards with a body-size heading and a small note; tables with uppercase micro headers, hairlines and right-aligned tabular numbers. Charts are Apache ECharts with the anatomy from the data-viz method: bars at most 24px wide with 4px rounded tops and a sheet-coloured gap between stacked segments, 2px lines, hairline gridlines, no axis lines, a legend only for two or more series, a tooltip on the sheet. Series colours are `--chart-1` gold `#b8850a`, `--chart-2` blue `#2f6fa8`, `--chart-3` terracotta `#b4522f` (dark: `#ad8718`, `#5b93d0`, `#cc6e48`), validated for lightness, chroma, colour-vision separation and contrast on the sheet; failures use the error colour. Never a dual axis: measures of different scale get their own chart. The login page is one centred sheet.
